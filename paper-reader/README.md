# 论文精读助手 · M0 解析层

方案见上层目录的 `PAPER-READER-SPEC.md`。这里只实现其中 §3 的取源与解析，
是整条链路的地基——解析质量不达标，后面的讲解、提问、诊断全都建立在错误文本上。

## 这一版做了什么

- 从 arXiv 取 LaTeX 源码（不走 PDF，公式保留原始 LaTeX）
- 递归展开 `\input` / `\include` 子文件（很多主 tex 只是骨架）
- 展开作者自定义宏（`\newcommand`），避免公式里留 `\ve{y}` 这种记号
- 剔除标题区（`\maketitle` / `\title` / `\author` / abstract）
- **表格结构化**：`tabular` 按行列切成 `header` + `rows`
- **算法环境分离**：伪代码单独存放，不混进正文
- **阅读计划**：按一级章节聚合，标出必读 / 略读 / 按需 / 附录，估算调用量
- 按章节切分，段落切成论证单元（先用段落近似）
- 抽取公式（保留 LaTeX 原文与 label）、图表（路径 + caption + label）
- 五项质量自检，判定能否进入 M1

**没有做**：PDF 解析、HTML 解析、视觉兜底、模型调用。这些是后续阶段。

## 用法

```bash
python m0_fetch_parse.py 1512.03385
python m0_fetch_parse.py https://arxiv.org/abs/1512.03385
python m0_fetch_parse.py 2010.11929v2 --keep
```

只依赖 Python 标准库，不需要 pip 安装任何东西。

| 参数 | 说明 |
|---|---|
| `--out` | 输出目录，默认 `out/` |
| `--cache` | 源码缓存目录，默认 `cache/`；同一篇重复运行不再下载 |
| `--keep` | 保留解压出的原始源码，便于排查解析问题 |

## 输出

```
out/<arxiv-id>/
  paper.json     结构化结果，字段对应 SPEC §7.1
  report.txt     与终端一致的质量报告
```

`paper.json` 关键字段：

- `meta`：标题、作者、摘要、arXiv 版本
- `outline`：章节树（含没有直接正文的纯标题章节、`appendix` 标记）
- `segments[]`：论证单元，含 `text` / `section` / `formulas` / `figures` / `tables`
- `readingPlan`：按一级章节聚合的阅读计划
- `parseQuality`：五项检查、统计、悬空引用明细

## 阅读计划

长论文逐段讲不现实。SAM 3 有 268 段，按每段一次调用算，光讲解就要 268 次——
用户读到第 50 段就会放弃。所以在打开论文前先告诉他结构：

```
角色     章节                        段数    字数
必读     Introduction                 6    4587
必读     Model                       16    7892
核心     Experiments                 13    8203
可略读    Related Work                 4    4119
附录     Model Details               48   25649
```

核心 52 段 · 略读 4 段 · 按需 211 段 · 可跳 1 段
只讲核心约需 52 次调用，全讲约需 268 次

**两个判定细节**：

1. **必须识别 `\appendix`**。LaTeX 里附录的 `\section` 仍编号成 A/B/C，级别不变，
   不跟踪的话「Model Details」48 段会被当成正文核心章节。
2. **正文一级章节默认核心**。算法、数据构建这些章节标题往往不含 method/model
   这类词，纯关键词匹配会漏掉真核心（SAM 3 的「Data Engine」就是这样被判成按需的）。

角色只是启发式，不调模型。它的用途是让用户圈定范围，而不是替用户决定。

## 质量自检

| 指标 | 阈值 | 不达标说明 |
|---|---|---|
| 章节数 | ≥ 4 | 结构识别失败 |
| 段落中位数 | 50–1500 字符 | 过短=切碎了（乱序），过长=没切开 |
| 超长段落占比 | > 4000 字符的段落 ≤ 10% | 整段没切开 |
| **表格残渣** | **== 0** | 表格文本漏进正文 |
| 悬空引用 | ≤ 2 | 引用了全文不存在的 label |

**「表格残渣」这一项是实测加的。** 首版没处理 `table` 环境，DINOv3 有 28 段、
SAM 3 有 58 段正文变成了 `Dataset && IN1k k-NN & ...` 和 `@ l ccccc @` 这种垃圾。
它不是"缺信息"，是**正文被污染**——如果直接进 M1，这些会被原样讲给用户。

判定不看 `&` 数量（正文里的 "Food & drink" 也有 &），而看**是否被切成很多
极短的片段**：4 段以上且 60% 的片段 ≤ 12 字符，才算残渣。

**两个指标被实测推翻过，记录在此避免重犯：**

1. **公式密度不是质量指标**。初版用「公式 ≥ 5%」当门槛，ResNet 被判不达标——
   它是实验型论文，全篇公式本来就只有两个。这是拿指标惩罚论文类型。
2. **平均段长会误伤长文**。DINOv3 是 16 万字技术报告，平均段长 805 字符、
   中位数 769，被判超标。改用中位数 + 超长占比，抓的是「切碎」和「没切开」两种
   真实失败，而不是段落偏长。

| ViT `2010.11929` | 78 | 25 | 9 | 12 | 3 | 4.7 万字 | 通过 |
| DETR `2005.12872` | 97 | 23 | 5 | 11 | 10 | 5.9 万字 | 通过 |
| SAM 3 `2511.16719` | 268 | 41 | 50 | 25 | 8 | 15.4 万字 | 通过 |

篇幅跨度 2.6 万–15.4 万字，全部通过质量自检。

**表格解析成功率差异很大，必须单独说明：**

| 论文 | 有数据行的表格 |
|---|---|
| DETR / ViT / AgriJetsonBench | 5/5 · 9/9 · 13/13（100%） |
| ResNet / PIDNet | 10/12 · 6/7（约 85%） |
| SAM 3 / DINOv3 | 16/50 · 10/33（约 30%） |

前几篇是普通论文，表格规整。SAM 3 和 DINOv3 是 Meta 的大型技术报告，
大量表格是**图片形式**（`\includegraphics`）或多层嵌套表头，行列切不出来。
正文污染已经清除，但表格内容拿不到——这部分要等视觉通道。

## 已知限制

- **表格解析成功率不均**：普通论文接近 100%，但大型技术报告（SAM 3、DINOv3）
  只有约 30%。图片形式的表格和嵌套表头切不出行列。正文污染已清除，内容缺失。
- **算法环境未验证**：`algorithm` 解析代码写了，但这 7 篇 CV 论文都没用到该环境，
  属于「没跑过」而非「跑通了」。
- **脚注、边注丢失**：`\footnote{}` 在清理时被删，其中可能有关键限定条件。
- **作者解析是尽力而为**：模板差异极大（`\and` / `\qquad` / `\centerline` + 上标 /
  `\author[*]{}` 一人一条），已做多路兜底，但个别模板（如 `2608.00927`）
  根本不用 `\author` 命令，作者会为空。
- **只走 LaTeX 路径**：没源码的论文（期刊、企业报告）直接失败，需要后续补
  HTML 与 PDF 降级。
- **未做版本一致性校验**：SPEC §3.7 要求的 v1/v2 比对还没实现。
