# 论文精读助手 · M0 解析层

方案见上层目录的 `PAPER-READER-SPEC.md`。这里只实现其中 §3 的取源与解析，
是整条链路的地基——解析质量不达标，后面的讲解、提问、诊断全都建立在错误文本上。

## 这一版做了什么

- 从 arXiv 取 LaTeX 源码（不走 PDF，公式保留原始 LaTeX）
- 递归展开 `\input` / `\include` 子文件
- 展开作者自定义宏（`\newcommand`），避免公式里留 `\ve{y}` 这种记号
- 剔除标题区（`\maketitle` / `\title` / `\author` / abstract）
- 按章节切分，段落切成论证单元（先用段落近似）
- 抽取公式（保留 LaTeX 原文与 label）、图表（路径 + caption + label）
- 三项质量自检，判定能否进入 M1

**没有做**：PDF 解析、HTML 解析、视觉兜底、模型调用。这些是后续阶段。

## 用法

```bash
python m0_fetch_parse.py 1512.03385
python m0_fetch_parse.py https://arxiv.org/abs/1512.03385
python m0_fetch_parse.py 2010.11929v2 --keep
```

只依赖 Python 标准库，不需要 pip 安装任何东西。

| 参数 | 说明 |
|---|---|
| `--out` | 输出目录，默认 `out/` |
| `--cache` | 源码缓存目录，默认 `cache/`；同一篇重复运行不再下载 |
| `--keep` | 保留解压出的原始源码，便于排查解析问题 |

## 输出

```
out/<arxiv-id>/
  paper.json     结构化结果，字段对应 SPEC §7.1
  report.txt     与终端一致的质量报告
```

`paper.json` 关键字段：

- `meta`：标题、作者、摘要、arXiv 版本
- `outline`：章节树（含没有直接正文的纯标题章节）
- `segments[]`：论证单元，含 `text` / `section` / `formulas` / `figures`
- `parseQuality`：三项检查、统计、悬空引用明细

## 质量自检

| 指标 | 阈值 | 不达标说明 |
|---|---|---|
| 章节数 | ≥ 4 | 结构识别失败 |
| 平均段长 | 30–800 字符 | 过短=乱序，过长=未切分 |
| 悬空引用 | ≤ 2 | 引用了全文不存在的 label |

**公式数只统计、不判定。** 初版曾用「公式密度 ≥ 5%」当门槛，结果 ResNet 这种
实验型论文被判不达标——那是论文类型差异，不是解析质量问题。指标本身写错了。

## 实测结果（2026-10-22）

| 论文 | 段落 | 章节 | 公式 | 图表 | 正文 | 结论 |
|---|---|---|---|---|---|---|
| ResNet `1512.03385` | 95 | 12 | 2 | 7 | 4.8 万字 | 通过 |
| ViT `2010.11929` | 81 | 25 | 3 | 12 | 4.9 万字 | 通过 |
| DETR `2005.12872` | 97 | 23 | 10 | 11 | 5.9 万字 | 通过 |

三篇的作者、标题、章节树均正确识别。

## 已知限制

- **表格未结构化**：`tabular` 内容是纯文本，行列关系丢失。表格往往承载核心结果，
  这是 M1 之前要补的。
- **算法环境未单独处理**：`algorithm` / `algorithmic` 里的伪代码会混进正文段落。
- **脚注、边注丢失**：`\footnote{}` 在清理时被删，其中可能有关键限定条件。
- **作者解析是尽力而为**：模板千奇百怪（`\and` / `\qquad` / `\centerline` + 上标），
  已加姓名形态兜底，但复杂模板仍可能出错。
- **只走 LaTeX 路径**：没源码的论文（期刊、企业报告）目前直接失败，需要后续补
  HTML 与 PDF 降级。
- **未做版本一致性校验**：SPEC §3.7 要求的 v1/v2 比对还没实现。
